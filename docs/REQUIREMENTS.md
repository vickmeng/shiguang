## 规划迭代（AI 段，2026-10-22 立项）

宏观设计：记录 → 逐条理解（一句话摘要）→ 用户画像（常驻引导）→ 知识库问答。记忆消费走「画像常驻 + 按需检索」（调研自 Cubox / ChatGPT memory / mem0 / claude-mem）；内容层三层：记录（事实）→ 摘要（记忆）→ 摘要向量（可重建派生索引，sqlite-vec）；主题不预存，画像汇总时由 AI 现抽。智能产物全存 sqlite 单文件。

| 迭代 | 需求 | 内容 | 闭环标准 | 状态 |
|---|---|---|---|---|
| 一 · AI 逐条理解 | MEM-01 | 提交先经 AI 分析（文字+图片）出一句话摘要，摘要 + 记录一起入库，记录页可见；AI 判无意义或调用失败则本条提交失败可重试（不入库） | 存一条 → AI 看懂 → 记录页看到摘要 | 未开始 |
| 二 · 用户画像 | MEM-02/03 | 摘要全量重写汇总画像（固定 5+1 槽位：身份概况/最近关注/兴趣爱好/在意的事/长期方向/其他；旧画像+新摘要仅作参考输入，习惯变化与久未关注内容自然淘汰），画像页只读不打扰 | 画像长出「AI 眼中的我」；记录页可见每条记录是否已纳入画像分析 | 实现已交付（2026-10-26，ai-user-profile），真机 AC-1~AC-9 走查待进行 |
| 三 · 知识库问答 | MEM-04 | 画像常驻注入 + 按需检索（关键词 + 标签先行，向量按需），回答带引用 | 提问 → 答出 → 点回出处记录 | 未开始 |
| 四 · 主动洞察 | MEM-05 | 「这条和你最近关心的事有关」式推送 | 方向保留，迭代三后再评估 | 待定 |

依赖：二 ← 一；三 ← 一 + 二；四 ← 二。

技术选型（2026-10-22 锁定）：**Mastra**（workflow/agent/evals，设计与实现须遵循其官方最佳实践，约束见 `AGENTS.md`）+ **Kimi**（OpenAI 兼容 API）+ **sqlite** 单文件。边界：不用 Mastra memory/storage，workflow 快照可丢弃；LangChain 全家桶已卸载。
