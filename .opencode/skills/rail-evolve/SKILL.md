# rail-evolve

基于当前聊天上下文和项目现状，识别可让后续 AI 写代码更强的地方，自由给出建议并落地用户认可的部分。

## 识别重点

- 用户反复修正、强调、纠正过的点
- 对话中暴露出的隐性约定与偏好
- 项目现状中反复出现的低效或易错之处
- 尤其当前的规范相关文件——纯格式化类（biome、prettier、editorconfig、eslint 的 format 类）不算；重点关注承载语义约束的规范，如 AGENTS.md、行为类规则、提交/命名约定、README 中的开发约定等

## 边界

- 不改代码逻辑、不加测试
- 不提议修改 rail-workflow 上游模板
- 写入前经用户确认
