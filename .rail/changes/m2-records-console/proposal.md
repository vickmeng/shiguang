# Proposal: M2 查询页面（m2-records-console）

## 1. 背景与动机

拾光（ShiGuang）M1「捕获与入库」已交付：PixiJS 桌面宠物窗（128×104，右下角，单击 toggle 输入框）、360×320 输入框（TanStack Form、5000 字上限、✓ 已拾光轻提示）、SQLite 单文件存储（`userData/shiguang.db`，better-sqlite3 + umzug）。数据已通过输入框持续落库到 records 表，但用户目前没有任何方式回看这些数据——M1 的查看方式只有外部工具打开 db 文件。

M2「查询页面」是应用首个正式界面，交付一个可操作的记录后台。用户对本次迭代的明确表态：M6 分析结果「先不管，还没到 M6」，本迭代不做任何预留；内容类型筛选 M2 不做，延后至 M4（截图接入时补）。

本次同时纳入两项技术债：REQ-UI-03 的 IPC 契约收敛，以及 M1 遗留的「开发者工具入口收敛到正式窗口」。

## 2. 需求与范围

### 功能描述

构建拾光的后台窗口（首个真实界面窗口），普通系统窗口、左右布局：左侧导航 + 右侧内容区。

1. **后台入口**：输入框窗口上加「打开后台」按钮；宠物左键唤出输入框行为不变；不加右键菜单；托盘不变（仅退出）。
2. **导航页面**：「记录」页（本次核心）+「设置」页（空占位，页面内留 TODO 标记，为 M3 开机自启、M9 导出等未来设置项留位）。
3. **记录页**：
   - 分页列表，按时间倒序。
   - 每条记录展示截断预览内容 + 存入时间。
   - 点击记录展开全文（展开后可折叠）。
   - 一键复制内容。
   - 删除需二次确认弹窗。
   - 勾选多条记录后可批量删除（批量删除同样走二次确认弹窗）。
4. **筛选**：关键词搜索 + 时间快捷预设（全部 / 今天 / 最近7天 / 最近30天）+ 自定义起止时间区间（精确到时分秒，2026-10-16 变更对齐新增），均可组合；分页大小可配（10/20/50/100，默认 20）。

### 范围边界

**M2 做：**

- 后台系统窗口（普通系统窗口，左右布局：左侧导航 + 右侧内容区），应用首个正式界面窗口，也是首个可聚焦「真实界面窗口」。
- 输入框窗口新增「打开后台」按钮作为入口；宠物单击行为、托盘（仅退出）均不变。
- 「记录」页：时间倒序分页列表、截断预览 + 存入时间、点击展开/折叠全文、一键复制、单条删除二次确认弹窗、勾选批量删除（同样二次确认）。
- 「设置」页：空占位 + TODO 标记。
- 筛选：关键词搜索与时间快捷预设（全部 / 今天 / 最近7天 / 最近30天）可组合；组合筛选无结果时正常显示空状态。
- DAO 扩展：`captureDao` 现有 `listCaptures(limit)` 无 offset / 无筛选 / 无搜索，本次扩展为支持分页 + 关键词 + 时间的查询与删除。
- 技术债（用户已认可）：
  - REQ-UI-03：IPC 契约收敛于 shared 包——含 M1 遗留的 `pet:clicked` / `input:blur` / `input:close` 分散注册治理进 `registerIpc` 汇总点；新增查询/筛选/删除通道时 payload/返回类型全部进 shared，preload 的 `ShiguangApi` 分组扩展，保持「shared 只放契约不放实现」原则。
  - 开发者工具入口收敛：M1 遗留 pet 文档债务，入口走右键 contextmenu 的既定计划在后台窗口落地。
- 性能待办落地：分页 / 懒加载 / 搜索索引（继承 REQUIREMENTS M2 节），保证高频使用数月后全文搜索与列表渲染不卡顿。

**M2 不做（明确排除）：**

- 内容类型筛选：M2 仅文字，类型筛选延后至 M4（截图接入时补）。
- M6 分析结果不预留任何结构 / 展示位置（用户明确「先不管，还没到 M6」，M6 再改布局）。
- 设置页不实现任何实际设置项（仅空占位 + TODO）。
- 不改宠物窗交互、不加右键菜单、不改托盘职责。

### 边缘场景处理（已对齐）

| 场景 | 处理方式 |
| --- | --- |
| 空库 | 显示引导性空状态文案（设计阶段细化） |
| 搜索无结果 | 显示引导性空状态文案（设计阶段细化） |
| 组合筛选无结果 | 正常显示空状态 |
| 删除保护 | 二次确认弹窗（已对齐） |
| 删光当前页 | 自动回退到前一页（或第一页） |
| 长文本 | 列表截断预览，点击展开/折叠全文 |

### 约束

- 窗口管理既定基线沿用：窗口创建幂等、显隐状态机集中主进程、几何纯函数化；新增后台窗 = 第三个 renderer 入口 + 第三个窗口模块 + preload 扩充。后台窗是首个可聚焦真实界面窗口，与现有双窗（frameless + transparent + alwaysOnTop）形态不同，按普通系统窗口处理。
- IPC 契约收敛：所有通道 payload/返回类型进 `packages/shared`，preload 的 `ShiguangApi` 分组扩展；shared 只放契约不放实现。
- 工程基线沿用：electron-vite 多入口、cjs preload（sandbox:false 既定决策）、Tailwind + shadcn 自写 primitives、三层测试策略（纯函数/状态机/组件 vitest+RTL，窗口行为手动走查）。
- 数据层边界：DAO 位于 `packages/ai/src/dao/captureDao.ts`，records 表字段（id/text/source_app/created_at）不变更语义，仅扩展查询能力。

### 验收标准

输入框点「打开后台」→ 后台窗口打开；记录页按时间倒序分页展示（预览 + 存入时间）；点记录展开/折叠全文；一键复制内容到剪贴板；单条删除弹二次确认、确认后记录消失且删光当前页自动回退；勾选多条批量删除（二次确认、确认后批量消失）；关键词 + 时间预设组合筛选正确，无结果时显示空状态；空库有引导性空状态；设置页显示 TODO 占位；`pet:clicked` / `input:blur` / `input:close` 等通道已收敛进 `registerIpc`，新增通道契约全部位于 shared。

## 3. 未来场景与扩展预判

- **内容类型筛选（M4）**：M2 不做，但筛选交互已为「关键词 + 时间」组合预留模式。建议应对方向：M4 接入截图时在现有筛选区追加类型维度，复用组合筛选逻辑；DAO 查询接口设计时入参用对象（而非位置参数），避免 M4 加维度时签名推倒重来。
- **M6 分析结果进入后台**：用户明确不做预留。建议应对方向：M6 时根据分析结果的实际形态再改记录页布局（如详情侧栏 / 独立 tab），不在 M2 结构上做任何假设性扩展。
- **设置页填充（M3 开机自启、M9 导出等）**：M2 仅空占位。建议应对方向：导航与路由结构一次成型，后续迭代只加页面不改编排。
- **数据量持续增长**：M2 已落分页/懒加载/搜索索引，但搜索索引方案（LIKE vs FTS5）的取舍在实现阶段验证。建议应对方向：若数万条记录下 LIKE 前缀/包含搜索仍流畅则保持简单；出现卡顿再上 FTS5 虚拟表，二者对 DAO 接口透明。
