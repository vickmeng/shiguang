# Design 格式规范

本文件定义 `.rail/changes/<slug>/design.md` 的强制格式。

## 必需段落（按顺序）

### 1. 概述
简述功能、关键行为与边界条件，明确范围内外的条目。

### 2. 验收标准
可测试或可人工核验的条件清单。使用 `- ` 列表项，**不要**使用 `- [ ]` 复选框。

### 3. 实现方案
- 接口与函数签名：对外暴露的关键契约，不含实现体
- 关键数据结构：核心类型定义及字段含义
- 关键骨架：仅限"必须按此方式实现否则会错"的约束，≤15 行
- 数据流 / 状态变更：从触发到最终状态的关键路径
- 技术决策：每条含决策内容、理由、备选方案及取舍原因
- 风险 / 取舍：`[风险/取舍] → 缓解/接受理由`，无则写"无"
- 技术债务：无则写"无"
- 影响文件清单

### 4. 回滚条件
什么情况下需要 revert 本次变更。
