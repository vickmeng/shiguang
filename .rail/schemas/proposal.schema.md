# Proposal 格式规范

本文件定义 `.rail/changes/<slug>/proposal.md` 的强制格式。

## 必需段落（按顺序）

### 1. 背景与动机

用户为何提出此请求，原始需求、参考文档、设计稿等上下文。尽可能保留原始措辞。

### 2. 需求与范围

经对齐确认后的功能描述，是 proposal 的核心，必须清晰无歧义。

包括：
- **功能描述**：需要构建什么的平实语言描述
- **范围边界**：本次明确要做和明确不做的条目清单。若存在已识别的极端场景、潜在冲突，应在相关条目中一并说明处理方向；若存在多种可行方向，给出对比分析和推荐意见

### 3. 未来场景与扩展预判

基于已确认的需求与边界，列出对未来可能出现的场景、风险、演进方向的预判。每个预判须附带**建议应对方向**；若存在多种可能，给出对比分析和推荐意见。按需列出，若目标很小可跳过。

注意：不在此讨论当下的需求细节或边界处理（那是「需求与范围」的职责）。

### 4. 相关引用

指向文件 / 文档 / 先前变更 / 关键源码位置的引用（根相对路径或绝对路径）。包括：需求对齐阶段读取的相关文档、用户提及的源码文件、探查中发现的关键代码位置。
